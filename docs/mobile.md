# Mobile development

Calendar mobile is Expo/React Native with Expo Router, NativeWind, native accessible controls, Inter, SecureStore and SQLite. Android and iOS share the same source. Node 24 LTS and Bun 1.4.3 are required.

Run `bun install --frozen-lockfile`, then `bun run dev:mobile`. Expo provides Fast Refresh. Install Android Studio/SDK to run `bun run --cwd apps/mobile android`. iOS simulator/native builds require macOS and Xcode. The Expo web export is useful for layout checks; it does not prove native behavior.

## Connect the local backend

Start the Rust backend on your computer and connect Google through the desktop app. For an Android emulator or USB-connected Android device with debugging enabled:

```powershell
adb reverse tcp:47821 tcp:47821
Get-Content .local/session-token | Set-Clipboard
```

In mobile Settings, use `http://127.0.0.1:47821/graphql` and paste that local token. The token is kept in SecureStore on Android/iOS, not bundled into the app. The Android preview allows HTTP for this development flow; settings reject non-HTTPS endpoints outside loopback/emulator addresses. An iOS simulator can connect to a backend running on the same Mac. A physical iPhone cannot reach your Windows loopback backend; hosted sessions/OAuth remain necessary for public use. The Expo web preview has no CORS bridge and is for layout/mocked testing; use the TanStack web app for real browser access.

## Behavior and storage

The top month grid includes every day and adjacent week padding. Swipe horizontally or use arrows to change months. Each date shows up to three event-color lines with a remaining count. Selecting a date shows its agenda below: all-day first, then start-time order. The plus button creates an event; tapping an event edits it. Failed saves keep the editor and inputs. Recurring edits affect only the selected occurrence. Times follow the current backend's Asia/Jakarta display zone.

Settings show calendars grouped by Google account and persist visibility/week-start preferences. Add/reconnect/remove Google accounts through the desktop or web app for now; mobile only removes its local backend connection. Changing/removing that connection clears in-memory and persisted snapshots and scheduled reminders. SQLite stores previously loaded ranges for offline viewing. Offline editing is disabled. Activity shows action summaries. PostHog client telemetry, remote push, background sync, and public sign-in remain future work.

The editor uses native iOS/Android date and time pickers, keyboard avoidance, validation and discard confirmation. Native haptics accompany date selection and successful saves. Local reminders are opt-in (at start or 5/10/15/30 minutes before), omit event titles, and schedule the next 50 timed events independently of the browsed month. Tapping an alert selects its date. Reminders use the last synced schedule while the app is closed; remote changes require another sync. OS notification permission and power policy apply. The web layout preview does not deliver notifications.

## Builds

`bun run --cwd apps/mobile export` verifies Android/iOS JavaScript bundles and a web layout preview. CI builds a self-contained Android preview APK with the generated development signing key and an unsigned iOS Simulator `.app` archive. These are preview artifacts, not Play Store/TestFlight releases. No credentials are packaged. Download artifacts from the PR workflow run.

`eas.json` is provided for optional later EAS builds. EAS requires your project/account setup. Physical-device iOS distribution requires Apple signing credentials and membership; simulator builds do not. Native projects are generated by Expo prebuild and ignored by Git. Keep platform configuration in app.json/app.config.ts/plugins rather than hand-editing generated projects. The production EAS profile disables Android cleartext HTTP; local previews keep loopback access.
